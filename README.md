# KOYO RADAR — где сейчас красные клёны в Киото

Мобильный сайт, который каждые 2 часа (05:17–23:17 JST) собирает статус осенней листвы из независимых японских источников, сверяет их между собой и показывает, куда ехать сейчас, завтра и послезавтра.

- **Сайт**: статический `site/`, без фреймворков. Работает офлайн (service worker), его можно добавить на главный экран iPhone.
- **Сборщик**: `collector/` на Python. У каждого источника свой адаптер; ошибка одного не ломает остальные (используется последний успешный снимок).
- **Данные**: `site/data/latest.json` — для сайта, `data/history/*.jsonl` — полная история изменений, `data/snapshots/` — последний успешный сбор по каждому источнику.

## Маршруты и посещённые места

Вкладки: **🍁 Листва | 🗓 Маршруты | ✓ Посещённые**. Все личные данные хранятся только в `localStorage` телефона. Есть экспорт и импорт в JSON: «Посещённые» → «Резервная копия».

- **Был здесь** — одним нажатием на любой карточке или остановке, без подтверждения. Дату можно изменить или стереть во вкладке «Посещённые».
- Три состояния места: свободно / запланировано (зарезервировано за конкретной датой) / посещено. Посещённые места никогда не попадают в автоматические маршруты ни на какую дату. Запланированные на другой день не предлагаются, пока не будут убраны из того плана или пока план не удалят.
- **↻ Пересобрать план** — заново загружает данные о листве и строит компактный маршрут (соседние остановки не дальше 4,5 км). Закреплённые 📌 остановки остаются. Места из текущего и предыдущего варианта сильно штрафуются, поэтому получается другой набор или район. Слабые места (score < 45) не берутся никогда: если альтернатив нет, это прямо написано.
- **Убрать** — место не вернётся в этот день, пока есть альтернативы. «Сбросить исключения дня» снимает это ограничение. «↶ Вернуть прошлый вариант» восстанавливает предыдущий план; хранится до 5 вариантов.
- Если отмеченное место стоит в будущем плане, план помечается ⚠ «нужна пересборка». Закреплённые остановки молча не удаляются.
- Часы работы источники не публикуют, поэтому для храмов принято «вход до ~16:00». Не попадают в автомаршруты: Сайхо-дзи (только по записи), дорога Arashiyama–Takao (только на машине), сплав Ходзу и поезд Сагано, а также сводные «районы» вроде «Район Такао», которые дублируют храмы.
- Логика: `site/planner.js`. Тесты: `node --test tests/js/planner.test.js` и `node tests/js/ui.e2e.js http://localhost:8000/` (Playwright, эмуляция iPhone).

## Насыщенные дни, замена остановок, вечерние подсветки

- **Насыщенность**: Спокойно (≤4 места, до ~15:30) / **Насыщенно** (по умолчанию, ≤6) / Максимум (≤8). Остановки сверх 4-й берутся только с оценкой 60 и выше, без «наполнителей». Все места дня лежат в радиусе ~6 км, общий путь не больше 14 км, соседние остановки не дальше 4,5 км. Время на месте зависит от места (дорожка 20–40 мин, большой комплекс 60–90). Часы работы берутся с Walkerplus (2026) у 112 мест, у остальных — типичные 9:00–16:00.
- **⇄ Заменить** у каждой остановки предлагает 3–5 альтернатив рядом (2,5 км; «Расширить радиус» — до 5 и 8 км) или вписывающихся между соседями. У каждой показаны состояние листвы, уверенность, дата наблюдения, дополнительное время и причина. Заменяется только выбранная точка, порядок меняется лишь когда без этого не уложиться по времени. Исходное место освобождается для других дней.
- **Вечер**: 1–2 подсветки, которые работают именно в этот день (учтены даты, «только пт/сб/вс и праздники», отдельные даты, выходные дни) и до которых можно успеть до последнего входа. Подсветка не дальше 7 км от последней дневной остановки, пара подсветок — не дальше 3 км друг от друга. Ранжирование идёт по **листве на территории** (та же система наблюдений), а не по популярности.
- **База подсветок** собирается раз в сутки (`collector/details.py`): Sōda Kyoto (JR東海, данные на 08.2026) + Walkerplus (2026). Ручная сверка с официальными сайтами лежит в `data/lightups_verified.json`. Сейчас подтверждены Кодай-дзи, Киёмидзу, То-дзи, Эйкан-до и даты Тион-ина. У Энтоку-ина и Умэкодзи на официальных сайтах анонса 2026 года нет, они помечены как «один источник». Расписания прошлых лет не используются.

## Транспорт: только пешком и общественным транспортом

- **Пешком**, если до следующего места ≤ 2 км по прямой (≈17 мин/км, для подъёмов вроде Сёгундзуки или Дзинго-дзи заложен запас). Иначе **автобус/метро/поезд**: в план закладывается ~18 мин на дорогу до остановки и ожидание плюс ~5 мин/км, для удалённых районов больше. Это запас для планирования, а не расписание: номера автобусов и время отправления не выдумываются.
- День группируется по транспортным связям. Удалённый район (Охара, Такао, Курама/Кибунэ, Камэока, Охарано, юг префектуры) — не больше одного в день и только с районом на той же линии (Такао↔Арасияма, Курама↔Итидзёдзи…). Ограничены число переездов и общее время в транспорте. Вечерние подсветки не тянут обратно в удалённую долину.
- **Google Maps**: отдельная ссылка на каждый переезд транспортом (`travelmode=transit`); подряд идущие пешие участки открываются одним маршрутом (`travelmode=walking` с промежуточными точками). Режим `driving` не используется нигде. Точки задаются японским названием и районом (`maps_q`, например «天授庵 京都市左京区»), поэтому Google находит само место, а не «Dropped pin». Проверенных Google Place ID у проекта нет: для них нужен платный Places API.
- В конце дня — кнопка «Обратно» до места ночёвки (по умолчанию 京都駅, меняется в «Даты поездки»).

## Домашняя база (BON Kyoto Station)

- Каждый день начинается и заканчивается в отеле (по умолчанию BON Kyoto Station, 京都府京都市南区西九条池ノ内町2). Время выхода вычисляется от первого места, возвращение — после последней подсветки. Дорога туда и обратно учитывается при выборе района и порядка остановок.
- Путь из отеля: пешком, если до места ≤ 2 км; иначе берётся быстрейшее из «пешком до станции Киото → поезд/метро» (JR Сагано, JR Нара, JR до Ямасины, метро), «пешком до станции То-дзи → Кинтэцу» (только южное направление) и «автобус от района отеля». Это запас для планирования, не расписание.
- Вечерняя подсветка предлагается, только если домой можно вернуться общественным транспортом. Консервативные пороги — до ~22:30 из города и до ~21:00 из удалённых районов. Точные последние рейсы проверяются по кнопке «Как добраться».
- Координаты отеля приблизительные (только для оценки времени). Ссылки Google Maps используют название и японский адрес, поэтому Google находит сам отель. Базу можно сменить в «Даты поездки → Домашняя база». Отель не считается местом: он не влияет на посещённые, Koyo Score и однообразие.

## «🍜 Где поесть»

Отдельная вкладка: ищет рестораны рядом (геолокация по нажатию или ввод адреса/станции) с рейтингом Google ≥ 4.0 и фильтрами — приём пищи, пешком (5–30 мин) или транспортом (15–45 мин), кухня, бюджет, ¥-уровень, «открыто сейчас». Сортировка: «Рекомендуемые» (байесовский рейтинг с учётом числа оценок и расстояния), «Ближе», «Рейтинг», «Дешевле». По кнопке «✨ Выжимка» данные запрашиваются только для одного места и кешируются в памяти вкладки.

Данные — только из официальных Google Places API (New) и Routes API через защищённый прокси `worker/` (Cloudflare Worker): ключи не попадают в публичный сайт. Пока прокси не развёрнут, вкладка честно показывает «не подключено» и не выдумывает рестораны. Как развернуть, сколько может стоить и как ограничить расходы — `worker/README.md`. Логика: `site/food-core.js`, интерфейс: `site/food.js`, тесты: `tests/js/food.test.js`, `tests/js/food.e2e.js`, `worker/test/`.

## Компактный мобильный интерфейс маршрутов

- Карточка остановки: время → иконка категории (SVG в стиле Lucide, `site/icons.js`) → короткое русское название (максимум 2 строки) → листва и одна ключевая деталь (последний вход или подтверждённая цена) → «Заменить · Был · Карта» (кнопки ≥ 44 px). Всё остальное — по нажатию: названия на трёх языках, Koyo Score, наблюдения, источники, фото, часы, цены, сайт, «Закрепить», «Убрать», «→ другой день».
- Переходы — одна строка «~14 мин пешком / ~30 мин транспортом», подробности и «Как добраться» раскрываются. Шапка дня — дата, район и цепочка 🏠 → N мест → 🌙 → 🏠. Критические предупреждения показываются сразу, остальное свёрнуто в «ⓘ N замечаний». Даты — горизонтальная лента, которая сама прокручивается и не растягивает страницу.
- Защита от переполнения: `min-width: 0` в flex/grid, `line-clamp: 2` для названий, `overflow-wrap: anywhere` для длинных японских строк, URL и цен; нижний отступ с `env(safe-area-inset-bottom)`. Тест `node tests/js/overflow.e2e.js http://localhost:8000/` проверяет ширины 320/375/390/430 и 260 px (крупный текст) с намеренно длинными строками.

## Разнообразие маршрутов (дополнительная функция)

- Категории мест в `data/places.json`: основной тип `cat` (храм/святилище, японский сад, парк, природная тропа, улица/квартал, река/набережная, гора/видовая точка, необычное место) и теги `tags` (например, храм с садом и лесной тропой). Подсветка — атрибут мероприятия, а не категория.
- Режимы «Лучшие места | Баланс | Разнообразие» (по умолчанию «Лучшие места») реализованы в отдельном модуле `site/diversity.js`. В режиме «Лучшие места» генератор работает **побайтно как раньше**: это проверяет тест на эталонных планах `tests/js/fixtures/baseline_plans.json`. «Баланс» и «Разнообразие» строят лучший план, затем вариант с небольшим бонусом за новые типы впечатлений (только для мест с оценкой ≥ 60). Вариант принимается, только если средняя листва не хуже (допуск 4/8 пунктов), ни одно подтверждённое место с оценкой ≥ 90 не потеряно, транспорт не хуже (≤ +20 мин и ≤ +1 переезд), а однообразие падает хотя бы на 5 пунктов. Иначе остаётся лучший маршрут, и это написано в плане.
- «★ Интересно само по себе»: курированный список мест, интересных без клёнов (Фусими Инари, Кинкаку-дзи, Рёан-дзи…). Такое место добавляется только в режиме «Разнообразие», только при свободном месте в дне и при отклонении не больше ~20 мин. Хорошей листвой оно не считается.
- «Однообразие: N%» = 30·доля повторяющихся категорий + 25·одинаковые типы подряд + 30·сходство соседних остановок (тип + теги) + 15·узость набора впечатлений. Считаются только дневные места; если категорий меньше трёх — «недостаточно данных».
- «Заменить» помечает альтернативы «Лучшие клёны», «Другой тип места» и «Ближе всего».

## Источники (проверено 17.11.2026)

| Источник | Что публикует на самом деле | Дата наблюдения | Как собираем |
|---|---|---|---|
| **Sōda Kyoto** (JR東海) | Фото сотрудников по ~77 местам | Дата съёмки в подписи к фото (`2026/11/16撮影`) | `modal.json` страницы; robots.txt нет |
| **JR Odekake** (JR西日本) | Отчёты самих храмов: 5 уровней, комментарий, точка наблюдения, координаты | «情報更新日» — дата отчёта места | HTML-таблица (ja + en для английских названий); robots разрешает только `/result/` |
| **Weathernews** | Статус по репортам пользователей (тонкая шкала), прогноз даты пика, координаты | `obsmon/obsday` — дата последнего репорта | `__NUXT_DATA__` страницы |
| **Japan Explorers** | **Модель** (высота + температура), окно пика и %, часть мест подтверждена датированной новостью | Только если дата есть в заголовке новости | HTML; % = позиция в окне сезона, **не** доля красных листьев |
| **Walkerplus** | Статус «提供元：JRシステム» — копия данных JR | Нет | HTML-списки (13 страниц); **не считается независимым подтверждением** |
| **Japan-Guide** | Полевые отчёты в блоге | Дата поста | Сайт отвечает **403** на автоматические запросы. Обходить защиту нельзя, поэтому только ручной импорт |

Сборщик представляется честно (`KoyoRadar/1.0 …`), соблюдает robots.txt (RFC 9309, побеждает самое длинное совпадение), делает паузу 2 с между запросами к одному хосту и не обходит 401/403/429.

## Как проверяется информация

- Оригинальный статус каждого сайта хранится как есть. Нормализованный статус хранится вместе с **диапазоном стадий**: например, JR «色づき始め» — это грубое ведро от «начала» до «почти пика».
- Вес свидетельства по типу: фото > отчёт храма > репорт с места > новость > прогноз > модель. Копии (Walkerplus) не учитываются.
- Свежесть считается от **даты наблюдения**, а не от даты обновления сайта. После 4 дней наблюдение помечается как устаревшее.
- **CONFLICT** ставится, когда два свежих независимых наблюдения расходятся на 2+ стадии. Поправка: старое наблюдение «расширяется» вперёд, потому что листва за неделю меняется.
- Уровень проверки: ✓✓ подтверждено (2+ источника согласны) / ✓ 1 источник / ⏳ устарело / ≈ только модель.
- **Koyo Score 0–100** — оценка привлекательности (стадия × качество подтверждения), а не процент красных листьев.
- Прогноз на завтра и послезавтра — простая фенологическая проекция (≈11 дней от начала окраски до пика, пик ≈8 дней) с учётом прогнозных дат пика от Weathernews и Japan Explorers.

## База мест

`data/places.json`: 137 мест с постоянными ID, названиями ja/en/ru, районом и **явными ключами каждого источника**. Нечёткого сопоставления нет: 光明寺 (Нагаокакё) ≠ 瑠璃光院, 正法寺 (Вадзука) ≠ 正法寺 (Охарано). Районы (`kind: "area"`, например «嵐山», «貴船周辺») — это отдельные записи, и они никогда не подменяют конкретный храм. Координаты берутся из ссылки JR на карту или из данных Weathernews; если их нет, ссылка на карту ищет место по названию.

Чтобы добавить регион Японии: напишите адаптеры для его страниц и добавьте места в `places.json` с полем `region`.

## Ручной импорт (Japan-Guide, сайты храмов, Instagram)

Скопируйте `data/manual/_TEMPLATE.json` в `data/manual/japan_guide.json` и заполните записи: место, статус, дата наблюдения, ссылка на первоисточник (обязательна). Файл можно править прямо в веб-интерфейсе GitHub: после коммита сайт пересоберётся.

## Запуск

```bash
pip install -r requirements.txt
python -m pytest -q tests          # парсеры на сохранённых реальных страницах
python -m collector.run            # живой сбор + сборка site/data/latest.json
python -m collector.run --offline  # пересборка из последних снимков
cd site && python -m http.server   # http://localhost:8000
```

GitHub Actions (`.github/workflows/update.yml`) запускает сбор по расписанию, коммитит данные и публикует `site/` на GitHub Pages.
